SmackMyRezUp Manual

A video player and exporter that runs ordinary footage — or a single image — through the experimental NVIDIA DLSS 5 neural-rendering runtime, using motion, depth and mask guides the way a game engine would supply them. This page covers every control, the file formats, and how to bring your own guides.

How it works

video / image → FFmpeg decode → resize to the output size (bilinear or Lanczos3)
             → guides: motion vectors  (block matcher, RAFT flow, or your _flow.mp4)
                       depth           (built-in proxy, Depth Anything, or your _depth.mp4)
                       control mask    (block-matcher uncertainty, or your _mask.mp4)
             → DLSS-NR evaluate, 1:1 at the output size
             → tone preserve → sharpen → LUT → display / export

The neural pass never upscales by itself. Upscaling is a deterministic resize first; the neural pass then redraws every output pixel at 1:1, which is why Native export (source size, no resize) gives the sharpest look of the original pixels.

Measured facts baked into the defaults: binding DLSSNR.MVec (even with zero vectors) removes most temporal jitter; binding DLSSNR.ControlMask changes the output on its own, more than the mask's content does; DLSSNR.Depth is ignored by the current runtime build but stays wired. The runtime exposes exactly one mask input and one set of intensity/structure/tone scalars per evaluation.

Video on the left, a scrollable control panel on the right, transport bar and timeline at the bottom. Every button and slider has a tooltip: rest the mouse on it for half a second. Click a group caption to collapse or expand it; turn the mouse wheel over the panel to scroll it — on a short window the Levels group sits below the bar until you do.

Guide files (sidecars)

A guide is an ordinary video that sits beside the movie with the same name plus a suffix. The player attaches it on load; the exporter takes it with a flag. Whether it is actually bound into the neural pass is a separate switch, listed in the last column.

FileCarriesPixel encodingBound when
<name>_flow.mp4Motion vectors, one per pixel: where the current pixel was in the previous frame (current → previous, the DLSS convention)RGB, yuv444p. R = dx, G = dy in source pixels, mapped from −24 … +24 to 0 … 255 (127.5 = no motion); B = 128. First frame all zero. +x right, +y down.Motion = Model and the Flow toggle on; exporter --flow-video with --mv estimated
<name>_depth.mp4Relative depthGrayscale (gray or yuv420p): bright = near, dark = far. Any consistent normalisation; the player inverts it into the runtime's 0 = near contract.DepthMap toggle on; exporter --depth-video (+ --nr-guides mv,depth). The current runtime ignores depth.
<name>_mask.mp4Where the neural pass should actGrayscale: white = process here, black = leave alone; grey values are soft weights, feathered edges are fine.MaskNR toggle on; exporter --mask-video with --nr-guides mv,mask
<name>_mask_<phrase>.mp4One mask per prompt phrase (from GenMask --layers)Same as aboveKept for per-object control; not bound by the player yet — the union file is what attaches
<name>_svr.mp4A SeedVR-restored version of the movieOrdinary colour videoLoaded as the input when you accept the prompt after a SeedVR job
  • Resolution may differ from the movie — the guide is rescaled to the source size on decode (a size mismatch that cannot be rescaled is skipped and logged).
  • Match the frame rate and frame count. If the guide is shorter, its last frame is reused.
  • Guides are calibrated to the source geometry, so the exporter drops them when --scaler lanczos resizes on the CPU first.
  • Encode near-lossless (-crf 6 or better): 8-bit values are already coarse — one flow step is 48/255 ≈ 0.19 px.

Make your own guides

Anything that can produce an image sequence can feed the player: a 3D renderer's passes, another flow or depth model, or a mask painted by hand. Write the frames as PNG, then encode them with the ffmpeg that ships beside the exe.

Motion vectors from raw values

For each pixel with motion (dx, dy) in source pixels, current → previous:

R = clamp( dx / 48 × 255 + 127.5 , 0, 255 )
G = clamp( dy / 48 × 255 + 127.5 , 0, 255 )
B = 128

If your source gives previous → current vectors (most optical-flow tools and Blender's Vector pass do), negate them first. Then:

ffmpeg -framerate 24 -i flow_%04d.png -c:v libx264 -preset fast -crf 6 -pix_fmt yuv444p movie_flow.mp4

Depth from any model or a Z pass

Normalise so near is bright. From a renderer's Z (distance) pass: value = 1 − (z − z_near) / (z_far − z_near), clamped 0…1, then ×255. Keep the normalisation stable across the shot or the guide will pulse.

ffmpeg -framerate 24 -i depth_%04d.png -c:v libx264 -preset fast -crf 6 -pix_fmt yuv420p movie_depth.mp4

Masks

White where the neural pass should act. Paint it, threshold a Cryptomatte/object-ID pass, or export a rotoscope matte. Soft edges are welcome.

ffmpeg -framerate 24 -i mask_%04d.png -c:v libx264 -preset fast -crf 6 -pix_fmt yuv420p movie_mask.mp4

Place the three files beside movie.mp4, reload it, and check each one in the MV / Depth / Mask views before binding.

From Blender

Blender's Vector pass is a true per-pixel geometric motion field with parallax — the same kind of data a game hands the runtime. Enable Vector, Z and Cryptomatte (or Object Index) in View Layer → Passes, save EXR, and convert with the formulas above (Vector stores previous→current and current→next in its four channels; use the first pair, negated). Blender's y axis points up, so negate dy as well.

Built-in generators

The Gen buttons run Python scripts from the tools\ folder with a Python that has torch, torchvision and transformers (ComfyUI's python_embeded\python.exe is the reference setup; GenMask needs transformers 5.x, plus sam2 for its fallback). First runs download model weights. SAM 3's weights are gated: ask for access at huggingface.co/facebook/sam3 and sign in (hf auth login, or set HF_TOKEN) - without that, GenMask falls back to Grounding DINO + SAM 2.1, which is not gated.

Prompt syntax for GenMask: lower-case phrases separated by periods — person. face. rather than "person and face". With --layers (what the button uses) you also get one _mask_<phrase>.mp4 per phrase. The prompt box's Models dropdown picks the sizes and is remembered: Fast (DINO tiny + SAM small), Balanced (DINO base + SAM base+), Best (DINO base + SAM large, about 3× slower; the default). First use of a size downloads its weights.

TensorRT: --backend trt compiles the flow or depth model into an engine on first use (5–30 s, cached in engines\) and runs 3–4× faster with matching output. Needs the CUDA Toolkit and the TensorRT SDK on PATH (or SMRU_TENSORRT_DIR), plus its Python wheel, onnx and onnxscript in the tools interpreter. Every RAFT engine is verified against the torch model before use, because TensorRT's kernel search is not reproducible.

Exporting

An export runs the headless exporter with the look you see: tone preserve and mix, sharpen, post-sharpen, Lanczos, NR smooth, motion mode, codec, the neural model and its intensity/structure/skin/automask, the LUT and strength, the Color window adjustments, the flow, depth and mask guides for the toggles that are on — and the DLSS state: with DLSS OFF the export skips the neural pass too (--dlss off), giving the plain resize with the effects.

The player writes the full exporter command line to SmackMyRezUp.log beside itself; the exporter's own log is SmackMyRezUpExport.log in your temp folder (%TEMP%). If an export fails, the message shows the exporter's last lines.

Troubleshooting

The Levels sliders are missing
They are below the bottom bar on a short window. Wheel over the panel to scroll, or collapse a group.
"… needs tools\make_….py"
The tools\ folder beside the player was deleted or could not be extracted (read-only folder?). Restart the player so it extracts again, or set SMRU_TOOLS_DIR to a checkout's tools folder.
"… needs a Python with torch"
Set SMRU_PYTHON or [Tools] Python= to a Python that has torch (ComfyUI's embedded one).
Export failed
The message shows the exporter's last lines; the full log is SmackMyRezUpExport.log in %TEMP%. The player's own log carries the exact command line.
My LUT disappeared
The path in the INI no longer exists. The player looks for the same file name in luts\ and repairs the setting; otherwise load it again.
DepthMap does nothing
Correct — the current runtime ignores depth. The Depth view still shows what it is being handed.
MaskNR looks different even with a blank mask
Binding the ControlMask changes the output by itself. Always A/B against MaskNR off.
Boiling detail on static shots
Lower Struct, raise Smooth, or set Motion to Zero.
A ghost of the previous shot after a cut
The exporter resets the neural history on detected cuts (--cut-reset on); raise --cut-warmup if the first frame after a cut is soft.

Better guides

The runtime was trained on a game's exact per-pixel motion field and depth buffer. Everything recovered from pixels is an approximation, so the guides are where the biggest gains remain.

Motion vectors

  • Resolution. GenFlow estimates at a 512 px long side and upsamples; run --size at the source width for HD material.
  • Model. RAFT-small trades accuracy for speed; RAFT-large or SEA-RAFT are drop-in upgrades with the same output contract.
  • Consistency. A forward–backward check (flow t→t−1 against t−1→t) finds occluded and unreliable pixels; zeroing those beats trusting a wrong vector, because the runtime rewards smooth, consistent fields.
  • Geometry. Fit the camera motion to the flow, render the dense field from the depth guide (parallax ∝ 1/depth), and keep RAFT only for the residual of independently moving objects. That reproduces the smooth, depth-shaped field a renderer produces.
  • Precision. The 8-bit ±24 px encoding quantises to 0.19 px; a 16-bit sidecar removes that.
  • Ground truth. Rendered footage can carry its real Vector pass — see From Blender.

Depth

  • Depth Anything V2 Large is markedly better than Small at the same interface; Video Depth Anything adds temporal consistency, which is what a per-frame model lacks most.
  • Until a runtime build reads DLSSNR.Depth, better depth improves the Depth view and nothing else — spend the effort on motion first.
